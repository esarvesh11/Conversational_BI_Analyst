
# 📊 US Labor Market Monitor

A conversational BI application that lets anyone explore US labor market data
by asking questions in plain English. Built entirely on Snowflake using
Cortex Analyst, Cortex COMPLETE, and Streamlit in Snowflake.

## ✨ What It Does

Ask a question like *"Which 5 states have the highest unemployment rate?"*
or *"Compare average hourly earnings in New York and Massachusetts"* — the
app returns:

- 📈 A **chart** of the answer (line, bar, or multi-series, auto-selected
  from the data shape)
- 📋 The **raw data** in a sortable table
- 🔎 The **generated SQL** for full transparency
- 📝 An **executive summary** generated by an LLM that highlights the key
  insight from the data

No SQL knowledge required. Just ask. 💬

### 💡 Example Questions

- "What is the unemployment rate in California?"
- "Which 10 states have the most job openings?"
- "Show hiring trends in Colorado since 2021"
- "How many employees work in each industry in Ohio?"
- "Compare the unemployment rate in Texas and New York"
- "What is the national unemployment trend since 2020?"
- "How did employment change in Washington between 2022 and 2024?"

## 🧩 How the Semantic Model Works

The semantic model YAML tells Cortex Analyst how to translate English into SQL.

**📑 3 logical tables:**
- `timeseries` — fact table (DATE, VALUE, GEO_ID, VARIABLE)
- `attributes` — dimension (MEASURE, INDUSTRY, FREQUENCY, UNIT, SA, source)
- `geography_index` — lookup (GEO_ID → GEO_NAME, LEVEL)

🔗 **Relationships:** timeseries joins attributes on VARIABLE, and geography_index
on GEO_ID. Every query joins all three.

🔤 **Rich synonyms:** Each column has a `synonyms` list so the AI maps user
language correctly. For example, "wages", "pay", "salary", and "compensation"
all resolve to `Average Hourly Earnings Of All Employees`.

⚙️ **Custom instructions:** 7 global rules encoded in the YAML prevent common
data pitfalls (see "Lessons Learned" below).

✅ **Verified queries:** 10 example question → SQL pairs teach Cortex Analyst
the correct patterns. New questions follow the same shape.

## 🐛 Lessons Learned (Non-Obvious Data Gotchas)

The semantic model went through several iterations before queries returned
correct results. These are the bugs I caught during testing:

| # | Bug | Impact | Fix |
|---|---|---|---|
| 1 | Every measure has both SA and NSA variants | Duplicate rows (2x) | Default `SEASONALLY_ADJUSTED = 'Not seasonally adjusted'` |
| 2 | `GEO_NAME = 'New York'` matches state + city | Duplicate rows | Add `LEVEL = 'State'` for state queries |
| 3 | National unemployment has 1,200+ demographic variables | Returns wrong series | Filter `VARIABLE_NAME LIKE 'Current Labor Force: Unemployment Rate, Monthly%'` for national |
| 4 | Wages exist per industry (~12 variants) | Ambiguous | Default `INDUSTRY = 'Total Private'` for headline wages |
| 5 | Percent values stored as decimal fractions (0.051 = 5.1%) | Misleading display | Multiply `VALUE * 100` in SELECT when `UNIT = 'Percent'` |
| 6 | JOLTS measures exist in Level and Percent units | Mixed series | Default `UNIT = 'Level'` for count questions |

All fixes are now in `custom_instructions` at the top of the YAML so
Cortex Analyst applies them automatically.

🎯 **Testing results:** 18 out of 18 natural language queries return correct
SQL and data after the iteration loop. See
`Semantic Model Testing Documentation.csv` for the full log.

## 🚀 Setup (To Reproduce)

**Prerequisites:** A Snowflake account with Cortex Analyst enabled and
access to the `SNOWFLAKE_PUBLIC_DATA_FREE` marketplace listing (free).

### 1️⃣ Create database, schema, warehouse, stage

```sql
CREATE DATABASE IF NOT EXISTS LABOR_MARKET_MONITOR;
USE DATABASE LABOR_MARKET_MONITOR;
CREATE SCHEMA IF NOT EXISTS APP;
USE SCHEMA APP;

CREATE WAREHOUSE IF NOT EXISTS LMM_WH
  WAREHOUSE_SIZE = 'X-SMALL'
  AUTO_SUSPEND = 60
  AUTO_RESUME = TRUE;
USE WAREHOUSE LMM_WH;

CREATE STAGE IF NOT EXISTS SEMANTIC_MODELS
  DIRECTORY = (ENABLE = TRUE);
```

### 2️⃣ Upload the semantic model YAML to the stage

Option A — SnowSQL:
```
PUT 'file://path/to/us_labor_market_monitor.yaml'
  @LABOR_MARKET_MONITOR.APP.SEMANTIC_MODELS
  AUTO_COMPRESS = FALSE OVERWRITE = TRUE;
```

Option B — Snowsight UI: navigate to the stage and use the `+ Files` button.

### 3️⃣ Create the Streamlit app

In Snowsight: **Projects → Streamlit → + Streamlit App**.
- Database: `LABOR_MARKET_MONITOR`
- Schema: `APP`
- Warehouse: `LMM_WH`
- Runtime: ⚠️ **Run on Warehouse** (not container — the `_snowflake` module
  required for Cortex Analyst API calls is only available on warehouse runtime)

Paste the contents of `streamlit_app.py` into the editor and click Run.

### 4️⃣ (Optional) Create the Snowflake Notebook

Follow the cell-by-cell guide in `notebook_content.md` to build the
modeling-decisions notebook.
